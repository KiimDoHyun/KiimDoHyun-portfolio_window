# 바탕화면 구조 재정의 & DOC 템플릿 표준화 설계

## 배경 (Why)

현재 포트폴리오 창을 열면 바탕화면에는 `내컴퓨터 / 프로젝트 / 기술스택 / 구글` 4개의 아이콘만 보이고, 이력·소속 정보는 전부 `프로젝트` 폴더 안에 한 단계 숨겨져 있다. 포트폴리오의 성격상 **"무엇을 어디서 했는지"가 창을 여는 순간 드러나야** 하는데, 지금 구조는 방문자에게 한 번의 클릭을 더 요구한다.

또한 `프로젝트` 폴더 안에는 다음과 같은 문제가 누적돼 있다:

1. **숨김 구조**: 와탭랩스(현직)·아라온소프트(전직)·대학 활동이 모두 동일한 래퍼 아래 나열되어 우선순위가 보이지 않는다.
2. **테스트 잔재**: `빈폴더`, `테스트폴더` 같은 개발 시 생성된 더미 폴더가 그대로 노출되고 있다.
3. **DOC 내용 공백**: 12개의 DOC 중 마크다운이 실제로 채워진 것은 `구알맛`, `SBL FEMS` 2건뿐이며, 나머지는 `projectDesc`가 비어 있다. 채우려고 해도 "어떤 섹션을 어떤 톤으로 써야 할지"에 대한 합의가 없어 작성이 정체된다.
4. **네이밍 일관성 부족**: `(주)아라온소프트`, `금오공과대학교 셈틀꾼` 등 접두어/단체명 중복으로 폴더 레이블이 길고 정돈되지 않았다.

이 설계는 바탕화면을 **포트폴리오 랜딩**으로 재배치하고, 앞으로의 DOC 작성을 정형화할 두 가지 **마크다운 템플릿**을 도입하여, "내용을 채우는 작업"이 바로 이어질 수 있는 토대를 만든다.

## 설계 규칙

- **스키마는 건드리지 않는다.** `PortfolioSchema`·`ProjectData`·`ResumeData` 타입과 `AuthoringNode` 유니온은 그대로 유지한다. 이번 작업은 **데이터와 문서만 만지는 저위험 마이그레이션**이다.
- **코드는 이름에 의존하지 않는다.** 프로덕션 코드는 id/type 기반으로 동작하므로 `portfolio.json` 변경이 렌더링·라우팅을 깨지 않는다.
- **DOC `contents.department`는 폴더명과 일치시킨다.** DOCProgram 헤더에 "소속" 값으로 노출되므로 상위 폴더 경로와 문자열이 동일해야 시각적 일관성이 유지된다.
- **테스트 픽스처는 건드리지 않는다.** `__tests__/` 안의 픽스처에 `"프로젝트"`, `"구글"` 등이 쓰이지만 이는 각 테스트의 자체 데이터이며 `portfolio.json`과 독립적이다.
- **이력서 / PDF 타입 확장은 이번 스코프 밖.** 파일 형식 확장은 별도 세션에서 함께 처리한다.

## DOC 템플릿 체계

12개의 DOC은 성격이 둘로 나뉜다. 각 DOC은 `projectDesc` 마크다운 본문에서 아래 두 템플릿 중 하나의 섹션 스켈레톤을 따른다.

### 🅰 프로젝트형 — "제품을 만들었다"

```markdown
# 개요
한두 문단으로 "무엇을 만든 프로젝트인가"와 역할. 배경이 있으면 여기에.

# 주요 기능
- 사용자/고객이 실제로 쓰는 핵심 기능 bullet

# 기술 스택
| 영역 | 기술 |
|------|------|
| Frontend | ... |

# 담당 업무
- 내가 맡은 부분 bullet (팀 프로젝트면 특히 중요)

# 기술적 도전
## 문제 1: XXX
(상황 → 해결 접근 → 결과)

# 성과
- 수치가 있으면 수치. 없으면 정성적 결과.

# 회고
무엇을 배웠고 다음엔 어떻게 할지.
```

**필수 섹션**: `# 개요`, `# 담당 업무`
**선택 섹션**: 나머지. 해당 없으면 **생략**하며 빈 제목을 남기지 않는다.

### 🅱 이니셔티브형 — "자발적 개선/문제해결 과제"

```markdown
# 배경 / 문제
왜 이걸 시작했나. 어떤 불편/리스크/기회가 있었나.

# 접근 방식
어떤 관점으로 풀었나. 선택지와 선택 근거.

# 내가 한 일
- 구체 액션 bullet (설계/구현/설득/도입 등)

# 결과 / 임팩트
- 변한 것. 수치 가능하면 수치.

# 배운 점
회고/다음에 적용할 점.
```

**필수 섹션**: `# 배경 / 문제`, `# 내가 한 일`, `# 결과 / 임팩트`
**선택 섹션**: `# 접근 방식`, `# 배운 점`.

| 영역 | 영향 | 비고 |
|------|------|------|
| `src/shared/lib/file-system/*` | 없음 | id/type 기반 |

| `src/shared/types/*` | 없음 | 타입 변경 없음 |

## 수동 검증

- [ ] `pnpm dev` 실행 후 브라우저에서 로그인 → 바탕화면에 아이콘 **정확히 5개**만 보인다 (`내컴퓨터 / 현직 / 경력 / 대학교 / 기술스택`)
- [ ] `현직` 더블클릭 → `와탭랩스/` 서브폴더가 보인다. 더 들어가면 DOC 4건이 나열된다
- [ ] `경력` 더블클릭 → `아라온소프트/` 서브폴더가 보인다. 더 들어가면 DOC 6건이 나열된다
- [ ] `대학교` 더블클릭 → `셈틀꾼/`, `컴퓨터공학과 학생회/` 서브폴더 2개가 보인다. 각 서브폴더에 DOC 1건씩 있다
- [ ] `기술스택` 더블클릭 → 기존과 동일하게 `MAIN_TECH / SUB_TECH` 두 폴더, 그 안의 IMAGE 노드들이 유지된다
- [ ] `구알맛` DOC을 연다 → 마크다운 본문이 기존 그대로 렌더된다. `doc_header`에 `소속: 아라온소프트`, `기간: 2023.03 ~ 2023.08`이 보인다
- [ ] `SBL FEMS` DOC을 연다 → 마크다운 본문이 기존 그대로 렌더된다. `소속: 아라온소프트`로 표시된다
- [ ] 아무 빈 DOC(예: `NMS 프로젝트 분리`) 더블클릭 → "본문이 준비 중입니다" 안내가 보인다. `소속: 와탭랩스`로 표시된다
- [ ] 상태바/라우트 breadcrumb이 새 경로를 따라 `/ KDH / root / 현직 / 와탭랩스 / NMS 프로젝트 분리` 형태로 정확히 표시된다
- [ ] `pnpm test` → 전체 테스트 통과 (특히 `portfolio.test.ts` round-trip)
- [ ] `pnpm build` → 성공
