# Portfolio DOC 본문 작성

[src/data/portfolio.json](../../../src/data/portfolio.json) 의 `DOC` 노드 `projectDesc` 를 **표준 구조의 마크다운으로 채우고**, **핵심 지표를 강조**하고, **보완이 필요한 지점을 명시**하는 반복 작업 스킬.

## 적용 시점

- 신규 DOC 항목 본문 작성, 혹은 빈 `projectDesc` 채우기
- 사용자가 초안/메모를 주며 "포트폴리오에 넣어줘", "정리해줘", "추가해줘" 요청
- 기존 `projectDesc` 에 후속 정보 이어붙이기
- 단일 DOC 노드만 수정 (다른 엔트리는 건드리지 않음)

## 레퍼런스 패턴

[`NMS 프로젝트 분리`](../../../src/data/portfolio.json#L46-L55) 를 서식 기준으로 삼는다.

## 표준 구조

```
# 프로젝트 소개
한 두 문단. "무엇을 · 왜" 한 줄로 드러나게.

---

# 프로젝트 정보
- **유형**: 사이드 / 업무 / 연구 등
- **역할**: 단독 / 공동, 담당 영역
- **사용 범위 / 기간 / 스택 / 현재 상태** 등 프로젝트 성격에 맞게

---

# 주요 성과
## 도입 배경 / 문제 상황
## (선택) 기존 도구/방식의 한계
## 설계 / 구현
## 도입 효과
## 남은 과제 또는 운영 종료
```

서브섹션 이름은 프로젝트 성격에 맞게 조정 (예: 분리 프로젝트 → `분리 방법`, 봇 프로젝트 → `알림봇 설계`).

## 강조 규칙

의미 있는 **지표·키워드에만** 강조. 문장 전체 bold 금지.

| 대상 | 표기 | 예 |
|---|---|---|
| 정량 수치 | `` **`값`** `` | `` **`20초`** `` , `` **`13 명`** `` |
| 기간·버전 | `` **`YYYY.MM`** `` | `` **`2024.07`** `` |
| 핵심 기술/도구 | `` **`이름`** `` | `` **`GitHub Actions`** `` |
| 개념 키워드 | `**텍스트**` | `**코드리뷰 문화 정착**` |
| 조건·제약 | `` **"... `값` ..."** `` | `` **"본인 외 `1 명 이상`의 approve"** `` |

Before/After 비교는 **표 + 개선폭 열** 로 정리 (NMS 참고).

## 보완 표시 규칙

추측 금지. 미제공 정보는 인용 블록으로 남겨 다음 라운드로 넘긴다.

| 표시 | 용도 |
|---|---|
| `> **[확인 필요]** ...` | 사실 확인·기본 정보 (시기, 스택, 역할 분담, 매핑 방식 등) |
| `> **[보완 권장]** ...` | 설득력에 직결되는 약한 고리 — 정량 수치 재구성 권유 등 |

동일 섹션에 여러 항목이면 `>` 줄바꿈으로 묶는다. 항목별로 **"무엇을 채워야 하는지" 가 구체적** 이어야 함 (단순 "스택 확인" 금지, "Slack 연동 스택 — Bot Token · Webhook · SDK 중 무엇" 처럼).

## 항상 점검할 체크리스트

사용자 초안을 받으면 아래가 누락됐는지 훑고, 없으면 `[확인 필요]` 로 남긴다.

- **유형** — 사이드 / 업무 / 연구
- **역할 분담** — 단독 / 공동(공동이면 본인 주도 영역)
- **사용 범위** — 본인·팀·전사, 인원 수
- **기간** — 제작 vs 운영 구분
- **스택** — 핵심 1~2 개
- **도입 효과** — 정량 (없으면 정성 체감), Before/After
- **현재 상태** — 진행 중 / 운영 / 종료

## 작업 흐름

1. 대상 DOC 노드 위치·주변 포맷 확인
2. 사용자 초안을 표준 구조로 재배치
3. 수치·키워드에 강조 표기
4. 누락 항목을 `[확인 필요]` / `[보완 권장]` 블록으로 남김
5. `projectTerm` 업데이트 (확정 부분만 채우고 불확실한 부분은 본문 안내)
6. 응답 요약에 다음 3 가지를 포함:
   - 이번 라운드에 추가된 핵심 정보
   - 새로 표시한 `[확인 필요]` 목록
   - 다음 라운드 우선순위 TOP 2~3

## 자기 검증

- [ ] JSON escape (`\n`, `\"`) 미파손 — `portfolio.json` 문법 유효
- [ ] 한 섹션에 강조가 과도하지 않음 (문장 전체 bold 금지)
- [ ] `[확인 필요]` 항목이 "무엇을 채울지" 구체적으로 기술됨
- [ ] 기존 DOC 헤딩 포맷 유지 (`# 프로젝트 소개` / `# 프로젝트 정보` / `# 주요 성과`)
- [ ] 사용자가 말하지 않은 사실을 임의 재해석·과장하지 않음

## 주의

- 데이터 파일만 수정. 렌더링 코드는 건드리지 않는다.
- 초안이 약하면 스토리를 지어내지 말고 `[확인 필요]` 로 남긴다 — 정직한 공백이 과장된 본문보다 낫다.
